# Puzzles do chess.io — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publicar até a coleção completa de puzzles válidos do Lichess no GitHub Pages, carregando pequenos pacotes somente durante o treino.

**Architecture:** Conversão offline da base CC0 em pacotes JSON gzip com manifesto por dificuldade e tema. O navegador seleciona e descompacta um pacote, usa chess.js para jogar a solução e guarda progresso local. GitHub Pages serve todos os arquivos; nenhuma API externa é necessária durante o treino.

**Tech Stack:** JavaScript ESM, chess.js 1.4.0, BoardView existente, Python 3 com csv/gzip/sqlite3 da biblioteca padrão e CLI zstd apenas na máquina de desenvolvimento; DecompressionStream e fallback gunzip local no navegador.

**Spec:** [Proposta, tamanhos e requisitos](../specs/2026-10-08-puzzles-design.md).

## Global Constraints

- Nome do produto: chess.io; preservar a aparência atual e as demais funcionalidades.
- Plano aprovado para implementação pelo usuário em 08/10/2026. Primeira entrega: 1.000.000; ampliação integral futura.
- Sem API durante o jogo, conta obrigatória, servidor de aplicação ou serviço adicional.
- Piloto de 100 mil; entrega inicial de 1 milhão; expansão para todos os registros válidos condicionada à medição integral.
- Pacotes de até 2.000 registros, 256 KiB compactados e 1 MiB descompactado; intervalos de rating de 200 pontos.
- Manifesto até 1 MiB compactado e 8 MiB descompactado; site inteiro até 750.000.000 bytes.
- Até três pacotes em memória; progresso guarda os últimos 5.000 IDs tentados.
- CSV bruto e arquivos temporários não entram no Git ou no dist. O build/deploy não baixa a base.
- Ferramentas de importação são usadas pelo desenvolvedor; jogadores não instalam nada.

## Review Focus

- Promoções, roque e en passant devem ser validados com a mesma biblioteca usada durante o treino.
- Uma resposta de carregamento atrasada não pode substituir o filtro/puzzle atual.
- Mate em um com várias respostas corretas deve aceitar qualquer mate legal.
- URL github.io com subpasta e arquivo gzip sem Content-Encoding devem funcionar.
- Falha de rede, filtro vazio ou armazenamento bloqueado devem permitir recuperação sem perder o controle do tabuleiro.

## Estrutura dos arquivos

| Arquivo | Responsabilidade |
|---|---|
| scripts/import-puzzles.py | Ler CSV em streaming, agrupar em sqlite temporário, converter e compactar; gerar manifesto e relatório |
| scripts/validate-puzzle-records.js | Processo persistente de validação chess.js por JSON Lines |
| scripts/check-puzzle-data.js | Conferir hashes, contagens, índices e orçamento da saída |
| data/puzzles/manifest.json.gz e pacotes *.json.gz | Dados estáticos versionados sem duplicação de temas |
| src/puzzle-loader.js | Carregar manifesto, sortear, descompactar e limitar cache |
| src/puzzle-session.js | Regras da tentativa, réplica, dica e revisão |
| src/puzzle-progress.js | Contadores e histórico local limitado |
| src/puzzles.js | Apresentar a tela usando BoardView |
| src/app.js, index.html, estiloXadrez.css | Integrar rota e interface existente |
| vendor/gunzip.js e sua licença | Fallback offline, com versão/licença registradas |
| tests/puzzle-*.test.js, tests/test_puzzle_import.py | Validar conversão, seleção, regras e progresso |

Formato de registro: `[id:string, fen:string, movesUci:string, rating:number, themeIds:number[]]`. No código de treino, decodificar para `Puzzle = { id, fen, moves:string[], rating, themes:string[] }`.

Manifesto v1: `{ schemaVersion:1, source:{url,sha256,downloadedAt,lastModified}, total:number, themes:string[], shards:Shard[] }`. `Shard = { path, sha256, gzipBytes, jsonBytes, count, ratingMin, ratingMax, themeCounts:[themeId,count][] }`. Campos numéricos e limites são validados antes de usar os dados.

### Task 3: Tentativas e progresso

Status: playing, solved ou revealed. `readPuzzleProgress(storage)` e `recordPuzzleAttempt(storage,{id,outcome})`, com outcome solved/failed/assisted; tentativa registrada uma única vez ao concluir, revelar ou trocar após erro.

- [x] Testar armazenamento inválido/bloqueado, contador que não duplica ao reabrir, corte em 5.000 IDs e retry assistido sem transformar tentativa anterior em acerto independente.
- [x] Rodar `node --test tests/puzzle-session.test.js tests/puzzle-progress.test.js`; confirmar falha inicial e implementar regras com chess.js, sem análise pesada do Stockfish em cada lance.

## Execução de 08/10/2026

Tarefas 1–4 implementadas e verificadas; tarefa 5 concluiu a preparação local de 1 milhão, sem push ou publicação. Coleção: 509 pacotes, 73 temas, 44.879.235 bytes com manifesto. Validação integral dos registros selecionados: zero inválidos e zero duplicados. Site gerado: aproximadamente 47,3 MB. A expansão para 6,15 milhões e publicação no GitHub permanecem etapas futuras, não necessárias ao uso desta versão local.

Revisão independente encontrou dois problemas corrigidos com regressões RED→GREEN: setas com foco no tabuleiro após conclusão e progresso quando localStorage falha. Também foi testada e corrigida a seleção ponderada quando a faixa de rating corta um pacote. Sem verificação visual por browser devido à rejeição anterior de file:// e proibição de contornar essa política; imagens locais foram inspecionadas e a interface testada por DOM simulado.

Verificação HTTP final: servidor localhost:3000 entregou o manifesto de 1 milhão e um puzzle real foi carregado/descompactado/resolvido pelo mesmo loader e sessão usados na interface.
